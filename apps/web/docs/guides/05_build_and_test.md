# 05. 컴파일, 빌드 및 테스트 규칙

## 1. 컴파일 및 빌드 안정성

- **미사용 코드 정리**: TypeScript 컴파일 시 미사용 변수나 임포트가 남아 있으면 엄격한 타입 체크 규칙에 의해 `npm run build` 빌드가 실패합니다.
  - 코드 작성 완료 및 커밋 전에는 불필요한 임포트와 미사용 변수를 완전히 정리하십시오.
- **커스텀 훅 사용**: 복잡한 상태 관리와 비즈니스 로직은 `src/hooks/` 또는 기능별 컴포넌트 디렉토리에 커스텀 훅으로 분리하여 컴포넌트를 가볍게 유지하십시오.

### 상태 변수·훅 삭제 시 검증 필수
- 상태 변수(`useState`), 커스텀 훅, 타입을 삭제할 때는 **삭제된 식별자를 참조하는残余 코드가 남지 않았는지** 반드시 확인하십시오.
- `npm run build` 전에도 grep으로 삭제한 변수명이 파일 내에 남아 있는지 1차 확인하면 `ReferenceError`를 예방할 수 있습니다.
- 불필요해진 `import` 구문과 타입 정의도 함께 정리하십시오.

## 2. 빌드 및 테스트 실행 제한 ⚠️

> **이 규칙은 최우선으로 준수해야 합니다.**

- **`./scripts/web/dev.sh` 실행**: 코드 작성 및 수정 후에는 `./scripts/web/dev.sh`를 실행하여 개발 서버를 기동하고 브라우저에서 검증을 수행합니다.
  - 개발 중 코드 변경 후 확인은 이미 실행 중인 `./scripts/web/dev.sh` 개발 서버를 통해 브라우저에서 검증합니다.
- **E2E 테스트 실행 금지**: 사용자가 명시적으로 "E2E 테스트 실행", "테스트해줘" 등을 요청하지 않는 한, AI 에이전트는 E2E(End-to-End) 테스트를 **자동으로 수행하지 않습니다**.
- **허용되는 검증 방법**:
  - 프론트엔드 빌드 검증: `npm run build` (Vite 빌드를 통해 타입 에러 및 빌드 성공 여부 확인)
  - 개발 서버 실행 확인: `./scripts/web-dev.sh` (이미 실행 중인 경우 재시작)
  - 브라우저 스크린샷 또는 DOM 분석을 통한 UI 검증
